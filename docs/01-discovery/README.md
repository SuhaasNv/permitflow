# 01 Discovery

The first thing written (17 Sep 2026), before any requirement, design or code: what problem the brief describes, who has it, and what "solved" would look like. Everything after this folder cites it.

| Document | What it holds |
|----------|---------------|
| `PROBLEM.md` | The problem in one paragraph, the personas (operator, officer, admin), the pain points of the current loop, the success criteria, and what the brief leaves open |

Read this first if you are new to the repository; it takes five minutes. The assessment brief itself is kept outside the repository (it belongs to the assessor); `../11-reviews/ASSESSMENT_TRACEABILITY.md` decodes it line by line.

Next: `../02-requirements/` turns the pain points into requirements with ids; `../../SCOPE.md` decides which of them are built.
