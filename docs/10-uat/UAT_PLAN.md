# User acceptance test plan and record

Acceptance scenarios for PermitFlow, run by a person in a browser against a deployed environment, with the result recorded. The automated form of every scenario is `frontend/e2e/scenarios/01..06-*.spec.ts` plus `journey.spec.ts`; the manual pass exists to see what the tests cannot (wording, layout, the feel of the loop) and to run on the deployed URL.

## Edge-case run (20 Sep 2026, final check before submission)

The scenarios above follow the happy paths and the six workflows. This run drives every refusal path and boundary the API has, in one script against the local stack (mock provider, seeded accounts, a second operator seeded by the script for the wrong-owner checks): `backend/scripts/uat_edges.py`, 166 checks, each printed as PASS or FAIL with the response that failed. Result: **166 of 166 pass** on `dev` after the fixes listed in `CHANGELOG.md` ("Final check"). Every error response was also checked for the standard `{ "error": { "code", "message" } }` body. The deployed environments were not reachable from the session's sandbox (outbound policy), so this run is local only; the deployed development environment keeps its earlier records above.
